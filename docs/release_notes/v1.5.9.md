# Pixora v1.5.9 — cloud diamonds, session analytics, tech stack refresh

**Release date**: 2026-04-18
**Focus**: monetization resiliency + analytics foundation + dependency modernization.

## ES — Notas para usuarios

**Lo nuevo en esta versión**:

• **Diamantes ahora se guardan en la nube** cuando inicias sesión con Google. Si cambias de teléfono o desinstalas la app, tus diamantes te siguen. Sin cuenta, los diamantes se acumulan localmente y se protegen automáticamente al iniciar sesión (conservamos el balance más alto entre tus diamantes locales y los de tu cuenta).
• **Generador IA**: para gastar diamantes en generar imágenes con IA hay que tener cuenta — así tu historial queda protegido y nadie puede abusar del sistema.
• **Ads mejorados**: actualizamos al SDK de AdMob más reciente. Ads más estables y mejor rendimiento.
• **Multi-dispositivo**: si abres Pixora en dos teléfonos con la misma cuenta, los diamantes se sincronizan al instante.
• **Stories y Day Cycle ya rotan correctamente**: arreglamos un bug donde los frames periódicos no actualizaban el wallpaper.
• **Doble reloj en pantalla de bloqueo arreglado**: ahora solo se ve el reloj del sistema.
• **Nuevo en Settings**: toggles para esconder reloj, batería, RAM, disco y ecualizador del wallpaper.

**Seguridad anti-abuso**:
• Rate limit: máximo un ad cada 3 segundos (previene scripts que farmeen).
• Cap diario: 500 diamantes/día por cuenta.

## EN — User-facing changes

**What's new in this release**:

• **Diamonds now sync to the cloud** when signed in with Google. Switch phones or reinstall and your diamonds travel with you. Without an account, diamonds accumulate locally and are protected automatically on sign-in (we keep the higher of your local or cloud balance).
• **AI Generator**: spending diamonds on AI image generation now requires an account — your spend history is protected and no one can abuse the system.
• **AdMob upgrade**: latest Mobile Ads SDK for better stability and performance.
• **Multi-device**: open Pixora on two phones with the same account and diamonds sync instantly.
• **Stories & Day Cycle rotation fixed**: periodic frame rotation now properly refreshes the wallpaper.
• **Double clock on lock screen fixed**: you only see the system clock now.
• **New in Settings**: toggles to hide the clock, battery, RAM, disk, and equalizer overlays.

**Anti-abuse safeguards**:
• Rate limit: max one ad every 3 seconds.
• Daily cap: 500 diamonds per day per account.

## Technical notes

### Backend (Supabase)

Migration applied: `20260418_credits_and_sessions_v1.sql`.

New tables:
- `user_credits` — balance, total_earned, total_spent, ads_watched, earned_today, rate-limit timestamps, first/last spent timestamps. RLS: users own their row.
- `credits_audit` — every transaction (earn, spend, login_sync) with delta, new_balance, reason, JSONB metadata. Users can read their own audit, writes only via SECURITY DEFINER RPCs.
- `user_profile` — aggregates per user (first_login_at, last_login_at, last_active_at, login_count, app_version, device_platform, locale).
- `user_sessions` — one row per login with microsecond-precision `started_at`, device model, Android version, locale, JSONB metadata.

New RPCs (all `SECURITY DEFINER`, `SET search_path = public`):
- `earn_credits(amount, metadata)` — atomic insert-or-update with 3s rate limit and 500/day cap. Audited.
- `spend_credits(amount, reason, metadata)` — atomic decrement, fails with `insufficient_credits` if balance too low. Audited.
- `sync_local_credits(balance, earned, ads)` — MAX merge on first login, audited with `login_sync` reason.
- `log_session(app_version, device_model, android_version, locale)` — inserts session row + upserts user_profile aggregates.
- `heartbeat()` — updates `last_active_at` (no-op if not authenticated).

Realtime enabled on `user_credits` so cross-device balance updates propagate instantly.

### Android (Kotlin)

**Multi-process SharedPreferences fix for Workers** (follow-up to v1.5.9-pre story-apply fix):
- `StoryWorker`, `AutoRotateWorker`, `DayCycleWorker` now send a `com.orbix.pixora.WALLPAPER_PATH_CHANGED` broadcast with the new path/glow/caption as Intent extras after writing prefs.
- `PixoraWallpaperService` registers a receiver that re-writes those values from inside the `:wallpaper` process — this syncs the local SharedPreferences cache (disk write is a no-op, but in-memory cache updates) and triggers the existing `OnSharedPreferenceChangeListener` debounced reload. Fixes the stale cache that kept showing old frames for hours.

**Lock-screen overlay leak fixed**:
- New `keyguardReceiver` in `PixoraWallpaperService` forces a redraw on `ACTION_SCREEN_ON/OFF/USER_PRESENT`.
- `forceHideOverlays` flag used during the final frame before sleep so the cached lockscreen frame has no clock/rings/caption baked in.
- `KeyguardManager` is now the authoritative lock-state source in `drawFrame()`, cached as a lazy property.

**User-controlled overlay toggles**:
- New Settings section with 5 SwitchListTile rows (Clock, Battery, RAM, Disk, Equalizer). Instant apply via `OVERLAY_SETTINGS_CHANGED` broadcast to the `:wallpaper` process.
- `SystemRingsRenderer.showRam` and `.showStorage` properties; when RAM is hidden and Storage visible, the storage ring slides up into the RAM slot.
- `MainActivity` exposes `getOverlayVisibility` / `setOverlayVisibility` method channel handlers.

### Flutter / Dart

**`CreditService` refactor** (hive-cached, server-synced):
- `earnFromAd()` writes through to `earn_credits` RPC when logged in; accumulates locally otherwise.
- `spend(amount, reason)` requires auth, calls `spend_credits` RPC, throws typed `CreditError` on all failure modes.
- `syncAfterLogin()` calls `sync_local_credits` RPC with MAX merge; subscribes to realtime balance updates.
- `onSignOut()` unsubscribes and zeroes local balance (so the next signed-out earning starts fresh).
- `CreditError` typed exception with codes: `not_authenticated`, `rate_limited`, `daily_cap_reached`, `insufficient_credits`, `invalid_amount`.

**`AuthService` session hook**:
- On successful `signInWithGoogle`, fires `log_session` RPC with device info (model, Android version, locale, app version) and calls `CreditService.syncAfterLogin()`. Both run fire-and-forget so sign-in UX doesn't block.
- On `signOut`, calls `CreditService.onSignOut()`.
- Device info collected via `device_info_plus` (new dependency).
