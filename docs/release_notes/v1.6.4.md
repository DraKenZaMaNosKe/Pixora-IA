## What changed (deeper)

### 🗂️ Catálogo migrado a Postgres (`411a35f` + `c907ff3`)

Reemplaza el `wallpaper-images/catalog.json` (180 KB descargados completos
cada 6h) por una tabla Postgres queryable con índices.

**Beneficios reales:**
- Queries server-side: filtros por categoría/tags/búsqueda devuelven solo lo
  necesario (~5 KB en lugar de 180 KB)
- Full-text search nativo (`tsvector` con name+description+tags) +
  trigram para tolerancia a typos
- `trending_score` con decay exponencial 14 días, recalculado en demand
- Updates de catálogo sin re-deploy: cambias un nombre via Supabase Studio
  y se ve en 30s
- Constraints en SQL (length, regex, enums) → Postgres rechaza datos malos,
  no la app

**Migración cuidadosa:** el cliente Dart usa una cadena de fallbacks
(Postgres → JSON Storage legacy → Hive cache local) así que si por alguna
razón Postgres está offline, la app sigue funcionando con la fuente anterior.

**Esquema (5 archivos en `supabase/migrations/`):**
- `001_schema` — tabla, enums, trigger updated_at, COMMENT ON cada columna
- `002_indexes` — 6 partial btree + GIN tags/tsvector + trigram
- `003_functions` — RPCs view/install/share + search + recompute_trending
- `004_rls` — read public published, write service_role only
- `999_rollback` — rollback completo en orden de dependencia

### 📊 Telemetría granular (`1742a33`)

Dos tablas nuevas para entender qué wallpapers funcionan y cuánto revenue
generan los ads.

**`wallpaper_events`** — 1 row por view/install/share/favorite con
anti-spam unique index `(device, wallpaper, minute)`. Cada acción del
usuario en la app se registra fielmente, listo para análisis cohortal.

**`ad_events`** — 1 row por impresión de ad con placement
(`wallpaper_apply`, `aura_play`, etc.), wallpaper_id opcional para
atribución de revenue, y campo `shown` para distinguir ad servido de
no-fill/error. Soporta interstitial/rewarded/banner/native (interstitial
es el único activo hoy).

Vistas admin pre-calculadas: `admin_user_stats`,
`admin_wallpaper_breakdown`, `admin_ad_revenue_daily`, `admin_ad_users`,
con estimación USD basada en eCPM LATAM (interstitial $2.50 / rewarded
$8.00 / banner $0.60).

**Anti-fraude:** mismo device no puede registrar la misma view 2 veces en
el mismo minuto. Bloqueado a nivel de unique index, transparente para
el cliente.

### 🐛 Fix de install counter (incluido en `c907ff3`)

`ContentManager.downloadAndInstall` ahora llama `trackInstall()` después
del `setWallpaper` exitoso. Antes solo trackeaba `download` (descarga del
archivo) pero no `install` (aplicación efectiva), perdiendo la mitad del
funnel. También se wireó la ruta directa de `live_wallpaper_preview_page`
que bypaseaba `ContentManager`.

### 🏛️ Dashboard admin local (`e17a0ca`)

Herramientas en `tools/wallpapers/`:
- `import_catalog.py` — importer idempotente del catalog.json a Postgres
- `wp_admin.py` — CLI con comandos stats/daily/top-users/wallpaper/search
- `wp_admin_server.py` — server local en puerto 5757 que sirve un SPA
  con tabs zodiacales, búsqueda paginada, modal con thumbnails reales,
  feed de eventos en vivo, y sección de revenue con chart $/día

**Importante:** el dashboard NUNCA viaja en el APK. Vive en la PC del
admin, lee con service_role key desde KEYS_LOCAL.md, y conecta vía
proxy local a Supabase.
