## What changed (full developer changelog)

### User-facing
- **NEW:** `lib/features/pixora_daily/presentation/pixora_daily_page.dart` — Apple TV Widget concept (#01 from `docs/design/pixora_daily_concepts.html`). Replaces inline AutoRotate UI in Settings.
- **NEW:** `lib/features/wallpapers/presentation/widgets/pixora_daily_banner.dart` — featured discovery banner on Wallpapers home (right after HeroBanner).
- **REFACTOR:** `settings_page.dart` — removed inline AutoRotate UI (state, pickers, methods all moved). Single source of truth.

### Engine mutex
- **NEW:** `lib/core/services/wallpaper_engine_coordinator.dart` — singleton that brokers wallpaper Surface ownership between three engines:
  - AutoRotateService (rotates random wallpapers)
  - DayCycleService (morning/afternoon/evening/night)
  - StoryRotationService (Goku transformation, etc.)
- Each engine `claim()`s on start and `release()`s on stop. Activating any one preempts the others, preventing race conditions where multiple engines fight for the wallpaper.
- `lastPreempted` field on each service surfaces preempted engine for UX messaging ("Pixora Daily reemplazó a Day Cycle").
- `main.dart` calls `coordinator.syncFromNative()` at startup to recover state across app restarts.

### Ad reliability
- **REVERTED:** the 25s/60s safety timeout I added in v1.7.5. AdMob's own internal countdown was being misread as "ad broken / paused" by users. The native SDK always shows the close button eventually; trust it.
- **DOCUMENTED:** new pitfall E in `CLAUDE.md` so this lesson sticks.
- Net code: ~70 lines deleted, simpler flow, no behavior regressions vs original.

### Pact
- **PRODUCTO_TERMINADO.md exception #1** logged. Justification: AutoRotate is pre-existing feature getting UX rescue, not new feature. Eduardo's decision documented in anexo.
