## What changed (developer changelog)

This release fixes a regression introduced in v1.7.6 when we added the
`WallpaperEngineCoordinator`. The bug was visible: Pixora Daily showed
"ACTIVO" in the banner but the user's wallpaper never visibly changed.

### Root cause

When AutoRotate ran (every N minutes), the Worker correctly:
1. Selected a new wallpaper from catalog
2. Downloaded it
3. Updated `pixora_live` SharedPrefs with the new path
4. Broadcast `WALLPAPER_PATH_CHANGED` to the `:wallpaper` process

**But** if a previous wallpaper had set a `scene_id` (Goku Genkidama,
Mictlantecuhtli, etc. — canvas scene wallpapers), that scene_id stayed
in prefs and kept overlaying the rotated image. The rotation WAS
happening, but invisible under the stale canvas scene.

### Multi-layer fix

1. **`MainActivity.startAutoRotate`** clears `scene_id` and `interactive`
   in `pixora_live`, then calls `killWallpaperProcess()` to force a fresh
   Engine. Same pattern as `startDayCycle`.

2. **`AutoRotateWorker.setWallpaper`** now removes `scene_id` and sets
   `interactive=false` on EVERY tick (defensive — covers all rotations
   after the initial start).

3. **`AutoRotateWorker` broadcast** adds `clear_scene=true` extra. The
   `wallpaperPathReceiver` in `PixoraWallpaperService` respects it and
   clears scene_id from its in-process cache too (the `:wallpaper`
   process has its own SharedPreferences cache that doesn't auto-sync).

### Cross-mode coordination

Also closed a coordination gap: applying a manual wallpaper
(`setWallpaper`, `setLiveWallpaper`) while AutoRotate was active either
left the WorkManager job firing uselessly OR had AutoRotate overwrite
the user's canvas-scene choice 5 min later. Now both call
`AutoRotateWorker.stop()` before applying.

### UX polish

`ensureLiveWallpaperActive(forceShowPicker)` now skips the picker when
Pixora is already the active wallpaper. AutoRotate passes `false`
(quiet toggle, no jarring picker every time). DayCycle/Story keep the
default `true` (first-time activation expects the picker).

## Pending follow-ups (for v1.8+)

These are NOT blockers for v1.7.9 release but are documented for future:

- **Tier 2 — `WallpaperHealthService`**: UI honest status by querying OS
  state (`WallpaperManager.getWallpaperInfo()` + service alive check +
  WorkManager job scheduled check). Replaces the "trust Hive prefs" UI
  pattern. ~2-3 hours work.

- **Tier 3 — `WallpaperModeManager` (refactor)**: Single writer to
  `pixora_live` SharedPrefs with a sealed-class mode enum. Imposible to
  forget cleanup between modes. ~1 day work.

- **Battery optimization opt-out flow**: Although Freecess wasn't the
  root cause this time, requesting battery whitelist on first AutoRotate
  activation would harden against future Samsung aggressiveness.
